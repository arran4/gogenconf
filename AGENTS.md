# Generated artifacts and fixtures

`gogenconf` deliberately checks in only these generated artifacts:

- `cmd/`, `cmd/errors.go`, and `cmd/agents.md`: production CLI self-hosted by the pinned go-subcommand generator.
- `internal/nativeconfig/`: the standalone native runtime generated by gogenconf and used by the shipped CLI.
- `examples/generated/**`: runnable, reviewable generated examples.

Run `go generate ./...` to refresh them. Do not hand-edit generated files. The
generated runtime must never import `github.com/arran4/gogenconf` or `codegen`.

`docs/content/` and `man/man1/` are reproducible user-facing build artifacts:
they are generated locally for Hugo, integration, and release packaging, but are
not committed. `internal/cligen/man/` is temporary staging output and must never
be committed.

Generator regression output belongs in `codegen/testdata/*.txtar`, one readable
scenario per archive. Use `input/` and `expected/` for related file trees;
`options.json`, `error.txt`, and `stdout.txt` are documented optional metadata.
Update generated expectations deliberately with:

```sh
go test ./codegen -run TestGenerationFixtures -update
```

Use literals for tiny values, `fstest.MapFS` when only a tree shape matters, and
`t.TempDir()` only when compiling generated code or testing OS behavior. Txtar is
test data, never a production runtime format.

When generator behavior changes, update relevant txtar fixtures, a runnable
example when the feature is user-visible, README/docs, and checked-in generated
artifacts. Validate with `go generate ./...`, `go test ./...`, and the CI checks.

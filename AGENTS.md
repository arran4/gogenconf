# Agent Instructions & Engineering Standards

These rules govern automated coding agents and contributors working in `gogenconf`.

## Core Repository Contracts

1. **Document AST Representation Preservation vs Canonical Formatting**
   - Treat round-trip fidelity as a distinct contract from canonical formatting.
   - Unresolved `Document` and `Expr` ASTs must preserve exact input structure: unknown sections, unknown entries, blank lines, user comments (`#`), managed documentation (`##` in v1+), argument ordering, and string escaping.
   - Do not silently trim, rewrite, drop, or pre-normalize parsed fields or expressions during document loading or convenience accessors.
   - Canonical formatting (`Format`, `FormatExpr`) provides deterministic display formatting without source I/O.

2. **Schema, Evolution, and Migration Boundaries**
   - Registered `Migrations` operate transactionally on unresolved AST documents. They increment `config_version` only on successful execution.
   - Parsing, validation, and binding must never implicitly save or write files to disk.
   - `Schema.Enrich` adds missing fields/defaults and updates managed documentation while strictly preserving explicit user overrides, user comments, and unknown sections/fields.

3. **Deterministic Code Generation & Runtime Boundaries**
   - Code generation (`codegen.GenerateModel`, `codegen.GenerateBinder`, `codegen.GenerateRuntime`) must be deterministic, inspectable, and idempotent.
   - Generated files carry `Code generated by ... DO NOT EDIT.` headers. **Never hand-edit generated files** (`*_generated.go`, `cmd/*`, `docs/content/*`, `man/*`). Edit the corresponding generator source or `README.md` instead.
   - The generated native configuration runtime (`codegen.GenerateRuntime`, checked in under `internal/nativeconfig`) must maintain zero runtime dependencies on `github.com/arran4/gogenconf`.

4. **Environment, Filesystem, and Boundary Testing**
   - Treat environment variables, process globals, file paths, and external I/O as boundary dependencies. Resolve them at application entry points and pass explicit typed options/readers to inner logic.
   - Do not construct synthetic XDG desktop sessions or mock environments in unit tests when pure functions or explicit options suffice.
   - Use `t.Setenv` only in focused, non-parallel adapter tests. Use `t.TempDir` for genuine OS path and file lifecycle semantics.
   - Maintain real boundary integration test coverage in `integration/` (`TestOutsideConsumer`, `TestRuntimeConsumerHasNoGogenconfDependency`, `TestInstalledCLIAndManual`, `TestReleaseTagRecovery`).

5. **Error Contracts and Public API Stability**
   - Wrap errors (`%w`) only when adding context or preserving caller-actionable error identity. Avoid mechanical wrapping at every stack frame.
   - Follow standard Go error classification and explicit typed error structures for schema and parse failures.
   - Do not silently alter public APIs, reduce supported compiler levels, or introduce unneeded external runtime dependencies.

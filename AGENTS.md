# Agent Instructions & Engineering Standards

These rules govern automated coding agents and human contributors working in `gogenconf`.

## Core Repository Contracts

1. **Document AST Representation Preservation vs Canonical Formatting**
   - Round-trip fidelity is a distinct contract from canonical formatting.
   - Unresolved `Document` and `Expr` ASTs must preserve exact input structure: unknown sections, unknown entries, blank lines, user comments (`#`), managed documentation (`##` in v1+), argument ordering, and string escaping (`document.go`, `expr.go`).
   - Do not silently trim, rewrite, drop, or pre-normalize parsed fields or expressions during document loading or convenience accessors.
   - Canonical formatting (`Format`, `FormatExpr` in `format.go`) provides deterministic display formatting without source I/O.

2. **Schema, Evolution, and Migration Boundaries**
   - Registered `Migrations` operate transactionally on unresolved AST documents (`migrate.go`). They increment `config_version` only on successful execution.
   - Parsing, validation, and binding must never implicitly save or write files to disk.
   - `Schema.Enrich` adds missing fields/defaults and updates managed documentation while strictly preserving explicit user overrides, user comments, and unknown sections/fields (`schema.go`).

3. **Deterministic Code Generation & Runtime Boundaries**
   - Code generation (`codegen.GenerateModel`, `codegen.GenerateBinder`, `codegen.GenerateRuntime`) must be deterministic, inspectable, and idempotent.
   - The generated native configuration runtime (`codegen.GenerateRuntime`, checked in under `internal/nativeconfig/`) must maintain zero runtime dependencies on `github.com/arran4/gogenconf`. Reference issue #10 before inventing another consumer gate.
   - Respect the documented pre-v1 API stability statement; do not invent compatibility promises. Still avoid breaking consumers incidentally when an additive seam suffices.

4. **Environment, Filesystem, and Boundary Testing**
   - Treat environment variables, process globals, file paths, and external I/O as boundary dependencies. Resolve them at application entry points and pass explicit typed options/readers to inner logic.
   - Do not construct synthetic XDG desktop sessions or mock environments in unit tests when pure functions or explicit options suffice.
   - Use `t.Setenv` only in focused, non-parallel adapter tests. Use `t.TempDir` for genuine OS path and file lifecycle semantics.
   - Maintain real boundary integration test coverage in `integration/` (`TestOutsideConsumer`, `TestRuntimeConsumerHasNoGogenconfDependency`, `TestInstalledCLIAndManual`, `TestReleaseTagRecovery`).

5. **Diagnostic Safety, Error Contracts, and Public APIs**
   - Validate untrusted configuration values at their boundary and keep secret material out of errors, diagnostics, generated samples and fixture snapshots (`binding.go:28`, `inspection.go:46`).
   - Preserve original error location/source span data where provided by the parser; issue #22 tracks structured contextual diagnostic wrapping.
   - Wrap errors (`%w`) only when adding context or preserving caller-actionable error identity. Avoid mechanical wrapping at every stack frame.
   - Do not silently alter public APIs, reduce supported compiler levels (minimum Go 1.25), or introduce unneeded external runtime dependencies.

## Generated Artifacts, Fixtures, and File Ownership

`gogenconf` deliberately checks in only these generated artifacts:

- `cmd/`, `cmd/errors.go`, and `cmd/agents.md`: production CLI self-hosted by the pinned go-subcommand generator.
- `internal/nativeconfig/`: the standalone native runtime generated by gogenconf and used by the shipped CLI.
- `examples/generated/**`: runnable, reviewable generated examples.

Run `go generate ./...` to refresh them. **Never hand-edit generated files** (`*_generated.go`, `cmd/*`). Edit the corresponding generator source, templates, or `README.md` instead. The generated runtime must never import `github.com/arran4/gogenconf` or `codegen`.

`docs/content/` and `man/man1/` are reproducible user-facing build artifacts: they are generated locally for Hugo, integration, and release packaging, but are **not committed**. `internal/cligen/man/` is temporary staging output and must never be committed.

### Test Fixtures and Goldens

- Generator regression output belongs in `codegen/testdata/*.txtar`, one readable scenario per archive. Use `input/` and `expected/` for related file trees; `options.json`, `error.txt`, and `stdout.txt` are optional metadata.
- Update generated expectations deliberately with:
  ```sh
  go test ./codegen -run TestGenerationFixtures -update
  ```
- Use literals for tiny values, `fstest.MapFS` when only a tree shape matters, and `t.TempDir()` only when compiling generated code or testing OS behavior. Txtar is test data, never a production runtime format.
- When generator behavior changes, update relevant txtar fixtures, a runnable example when the feature is user-visible, README/docs, and checked-in generated artifacts. Validate with `go generate ./...`, `go test ./...`, and CI checks.

## Agent Audit & Implementation Rules

- Read README and current open issues before refactoring.
- Audit code/test boundaries, report exact file/line evidence, and propose only untracked follow-ups in issue #27. Do not create broad refactor PRs under the guise of documentation.
- Never merge implementation automatically; request review and follow repository-specific instructions.
